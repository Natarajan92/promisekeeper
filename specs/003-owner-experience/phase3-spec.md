# Owner experience Phase 3: visual completion and demonstration

Authorization: 25 October 2026, after the owner instructed approval of completed
Phase 2, starting Phase 3 and completing the UX with better look and feel. Continue
the existing `003-owner-experience` checkout with accepted Phase 1/2 preserved.

## User outcome

The owner sees one coherent payment casebook, can scan evidence, advice and history
without technical identifiers dominating, and can demonstrate the complete honest
fictional workflow. This completes the authorized presentation work and original
roadmap UX-AC-15–18; it does not activate all future product/backlog features.

## Design and bounded scope

Use the existing approved six-token palette: ink #172d35, muted #52666d, blue #24576a,
workspace #f6f5ef, paper #ffffff, attention #805410. Keep Arial for text/data and
Georgia for identity/case headings; no external font, framework or dependency.
Use a consistent 4/8/12/16/24/32px spacing scale, tabular amounts, quiet surfaces,
strong selected case/navigation states and visible focus. Desktop has a compact
case rail and readable main paper; mobile retains the existing reachable case
selection and stacks financial/comparison rows. No sticky bar that covers content.

The chosen approach is a cohesive refinement of existing surfaces. A dashboard
rewrite would change navigation/pending-buffer behavior without helping the approved
decision journey; cosmetic color-only changes would leave technical selections and
history labels distracting. Preserve existing native controls and five tabs.

Polish the header, saved-copy selector, morning briefing, case rail, decision and
financial panels, evidence/timeline, review/confirmation, history and comparison.
Use friendly saved-copy/completion labels; exact IDs/codes remain accessible in
disclosures and still supply all requests and selection values. Give history human
event names and correctly label ascending pagination as Load more history. Keep
every original source, event sequence, hash and saved text intact. No new money,
commitment inference, lifecycle decision, request polling or write behavior.

## Acceptance

- UX3-01: the same visual hierarchy and restrained palette span all five sections.
  Controls have visible focus, text/status cues and measured readable contrast.
- UX3-02: selecting a friendly saved copy or investigation still selects its exact
  immutable identity. Comparison source buttons open the intended exact version;
  references are inspectable on demand. Opening disclosures performs no POST.
- UX3-03: friendly history names preserve exact event codes/payloads and server
  sequence; Load more history retains scope/pagination and historical links.
- UX3-04: at 1280×800, case-opening still exposes decision money/action; at 390px
  and actual 200% root text, all sections, amounts and controls remain reachable
  without sideways page overflow. Escape and return focus still work.
- UX3-05 / UX-AC-15–18: execute the approved five-minute route on a fresh isolated
  STUB/REFERENCE copy: disclosures, Morning Review, Northstar exact approval, Cedar
  claim/proof, preview/confirm U1, reinvestigate, compare originals and explicit closure.
  Record actual agent-operated elapsed time and checkpoints. It is not a measured
  human narration or usability study. Preserve a labelled saved-result fallback.
- UX3-06: no source/result/draft rewrite, regression in exact approval/changed-head
  recovery, provider/integration/agent/schema/API/dependency change or customer send.
