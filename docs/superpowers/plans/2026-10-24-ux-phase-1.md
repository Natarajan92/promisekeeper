# Payment workspace UX Phase 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Make the existing fictional payment workspace understandable and actionable without changing financial decisions or approvals.

**Architecture:** Extend the existing read-only case summary with reconciled money and only the current saved recommendation. Present a guided journey in React, alongside exact evidence, human decisions, and an explicitly approved-message clipboard handoff. Keep saved results and draft wording unchanged; friendly wording is a display concern.

**Tech Stack:** Existing React/TypeScript, CSS, FastAPI/Python, SQLite, Vitest and Playwright. No new dependencies.

**Spec:** Owner-approved five recommendations in the conversation and the implementation request of 24 October 2026. This bounded UX pass is distinct from original Gate I and does not close the five-owner study.

## Global Constraints

- Preserve fictional-only/no-authentication disclosure, explicit copy creation, no sending, existing financial rules and exact-version approvals.
- Do not read credentials or `.env`; verification uses explicit STUB settings and isolated databases.
- Never show a stale recommendation as current, an unknown balance as zero, or an unsaved/unapproved message as approved.
- Keep all display dates in Asia/Kolkata with an explicit IST suffix.
- Preserve exact saved result/draft text and hashes. Human studies and LIVE evidence are unchanged.
- Keep accounting local and excluded; no commit or push is requested for this UX iteration.

## Design

Retain the casebook identity: ink #172d35, muted text #52666d, blue #24576a, paper #ffffff, workspace #f6f5ef, attention #805410. Georgia headings and Arial body text remain. Use compact action groups and a numbered journey only for the actual evidence/recommendation/decision sequence. Keep left alignment, visible keyboard focus, narrow-screen wrapping and reduced-motion support. The visible improvement is purposeful navigation and readable status rather than decorative redesign.

Use existing case sections and add explicit links between them. Put owner decisions beside Findings and retain History access for existing journeys, so no destructive relocation or duplicate simultaneously mounted forms is needed. Demo setup receives friendly labels and explanations while exact fixture/clock IDs remain available. Approval copy writes only the exact saved approved text; clipboard failure gives manual selection guidance and never claims success.

## Review Focus

1. Evidence changes or elapsed wait time must clear the overview's current recommendation and review date.
2. Missing ledger/invoice evidence must retain unknown balance and honest labels.
3. Copy must be unavailable during unsaved edits, invalidation, pending review, or investigation; late clipboard completion must not claim a different draft was copied.
4. Cross-case navigation must not move decisions or edits to another case; history confirmation remains scoped.
5. WAIT/internal verification/CLOSE must guide users without promising a customer draft, an automatic reminder, or automatic closure.
