# PromiseKeeper: product experience gaps

**Date:** 25 October 2026. **Baseline:** `002-multi-agent-upgrade` / `1f13b86`. **Status:** audit and recommendations only.

Evidence labels and limitations are defined in [CURRENT_STATE_AUDIT.md](CURRENT_STATE_AUDIT.md#how-to-read-this-review). Current behavior below is source-verified unless labelled retained visual evidence. The effects on nontechnical owners are design hypotheses, not participant observations. Prior fixes are credited; this is not a list of features assumed absent.

## Overall assessment

The casebook already has a coherent visual identity and strong safety behavior. Its main weakness is information order: setup and agent internals take substantial space before the owner's money, evidence and next decision. A real product should let the owner act from those facts, with implementation details available on request. It does not need a CRM dashboard, chatbot or more charts to achieve that.

P0/P1/P2 below are **proposed competition priorities**, separate from the original MVP requirement priorities. Low/Medium/High describe relative implementation complexity on this codebase; benefit statements are expected, not measured.

## What should be preserved

- Existing plain draft-validation guidance, current-result action styling, source accessible-name fixes, narrow-screen case cards and clipboard fencing already solve earlier issues. Do not reimplement them.
- A recorded remainder for Cedar is contested; it must not become a verified amount to demand. Unknown never becomes zero.
- A new investigation/evidence update can invalidate approval; layout and labels must continue to reflect server eligibility and current draft head.
- Evidence time and arrival time have different meanings. Neither should be replaced by the browser's present day.
- A template fallback is an honest successful fallback when saved and valid. It should not be described as an LLM output or as failed payment reconciliation.

## Recommended boundary

Approve a small decision-first pass (UX-01/03/06/07/10, plus explicit case-focus behavior from UX-04), then a separately reviewed comparison increment (UX-02). Reuse existing reads and controls. Timeline enrichment, broad navigation changes and template wording should not expand those first phases.
